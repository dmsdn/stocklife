## 2 `GET /internal/purchases/history` — 여전히 없습니다 (오전판 그대로)

> **✅ 09-01 저녁 확인 — 구현되었습니다.** `InternalPurchaseController /history` ·
> `lookbackDays` 기본 180 · 상한 365. 저희 로컬판은 폐기하고 팀 판으로 갈아탔습니다.
> 감사합니다. 아래 본문은 오전판 기록으로 남깁니다.
>
> ⚠ **한 가지만 더 부탁드립니다 — 시각 기준.** `since = Instant.now() − days`
> 라 **실제 시각** 기준입니다. 시연 데이터의 구매는 05-15~09-01 이라 오늘은
> 손실 0 이지만, **2026-11-11 부터 가장 오래된 구매가 하루씩 조용히 빠집니다**
> (오류 없이 — 재구매 간격만 어느 날부터 짧아집니다). 저희는 호출에 365 를
> 명시해 2027-05 까지 밀어 두었습니다. 근본은 둘 중 하나면 됩니다:
> ① `lookbackDays <= 0` 을 「무제한」으로(지금은 기본 180 으로 떨어집니다)
> ② 기준 시각을 실제 시각이 아니라 세계 시각(`DEMO_NOW`)으로.
> ①이 한 줄이라 그쪽을 권합니다.

08-28 요청 그대로입니다. 공개판(`/api/purchases`)은 `@CurrentConsumer` 로
로그인 세션에서 사용자를 꺼내는데, **Agent 는 브라우저가 아니라 서버라
쿠키도 JWT 도 없습니다.** `InternalWishlistController` 를 따로 만든 것과
같은 상황이고, 질의·서비스·DTO 는 이미 있어 **매핑만** 필요합니다.

```java
@GetMapping("/history")
public ResponseEntity<?> getPurchaseHistory(
        @RequestHeader("X-Internal-Service-Key") String key,
        @RequestParam Integer memberId,
        @RequestParam(defaultValue = "180") int lookbackDays) { ... }
```

⚠ **인자는 `memberId` 입니다.** `consumerId` 로 받으면 시드 회원 1005 가
10,001,005 로 둔갑해 항상 빈 결과가 옵니다(`wishlist`·`history` 에서 이미
두 번 겪은 함정입니다).

**없으면 막히는 것**: 소비주기 예측 · 취향 매칭 · 재구매 추천 — 도구 셋과
그 위의 기능 넷이 통째로 섭니다. **남은 요청 중 이것만 시연을 막습니다.**

## 4 (신규) 채팅 첨부가 Agent 에 전달되지 않습니다 — 급하지 않음

`344c273` 의 첨부 업로드(`POST /api/chat/sessions/{id}/attachments`) 잘
봤습니다. 다만 지금 `ChatService.relay()` 는 첨부를 **메시지에 연결만 하고**,
Agent 로 보내는 `AgentChatRequest` 에는 첨부 정보가 없습니다 — 손님이 채팅에
사진을 올려도 Agent 는 사진이 있었다는 사실 자체를 모릅니다.

```java
// AgentChatRequest 에 칸 하나
private List<String> attachmentUrls;   // 이 메시지에 연결된 첨부의 접근 가능한 URL
```

`relay()` 에서 방금 연결한 첨부들의 URL 을 채워 주시면 됩니다.

**급하지 않은 이유**: 사진 검색의 주 경로는 `AiProxyController` 의
`/api/ai/photo-search` 릴레이(이미 있으심)라서, 시연은 그쪽으로 갑니다.
이 항목은 "채팅창 안에서 사진을 보내는" UX 를 살릴 때 필요합니다.
