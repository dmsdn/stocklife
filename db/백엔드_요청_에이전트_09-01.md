## ★1 `branch_jmy` 가 컴파일되지 않습니다 — 두 곳

`70ffe6a` ("8/31 마지막 저장")를 받아 `./gradlew compileJava` 를 돌리면 멈춥니다.
**브랜치 단독으로도 그렇습니다** — 저희 쪽 병합 때문이 아닙니다.

### ①-a `CartItemRepository.findConsumerIdsBySkuId` 가 정의되어 있지 않습니다

```
InventoryService.java:119: error: cannot find symbol
        List<Long> consumerIds = cartItemRepository.findConsumerIdsBySkuId(skuId);
symbol: method findConsumerIdsBySkuId(Integer)
```

재입고 알림 트리거(`notifyCartOwnersOfRestock`)가 부르는데, 그 메소드가
`branch_jsw`·`branch_jmy`·`branch_pew` **어디에도 없습니다.**

이런 모양이면 될 것 같습니다 — 참고만 하시고 편하신 대로 바꾸셔도 됩니다:

```java
@Query("select distinct cg.consumerId from CartItem ci, CartGroup cg "
     + "where ci.cartGroupId = cg.cartGroupId and ci.skuId = :skuId "
     + "and cg.consumerId is not null")
List<Long> findConsumerIdsBySkuId(@Param("skuId") Integer skuId);
```

⚠ `cg.consumerId is not null` 을 넣은 이유: 게스트 장바구니는 `consumerId` 가
비어 있어서 알림 대상이 될 수 없습니다. 빼면 `null` 이 섞여 들어갑니다.

### ①-b `Consumer.resetMonthlySpend()` 가 사라졌습니다 — **이건 판단이 필요합니다**

```
GradeResetScheduler.java:26: error: cannot find symbol
            consumer.resetMonthlySpend();
```

`70ffe6a` 에서 **등급 기준이 「월 지출액」에서 「누적 적립 포인트」로** 바뀌면서
`monthlySpendAmount` 필드가 없어졌는데, 그것을 0 으로 미는 월초 크론
(`GradeResetScheduler`)은 그대로 남아 있습니다.

> **그냥 되살리면 안 됩니다.** 새 모델에서 등급의 근거는 `pointEarnedTotal`
> (누적)인데, 월초마다 이것을 0 으로 밀면 **매달 1일 00:00 에 전 회원 등급이
> 초기화됩니다.** 「이번 달 얼마 썼나」와 「지금까지 얼마 쌓았나」는 다른 양입니다.

고르실 것은 둘입니다.

| | 어떻게 | 뜻 |
|---|---|---|
| ㉮ **스케줄러를 지운다** | `GradeResetScheduler` 삭제 | 등급이 누적 기준이면 초기화할 것이 없다 |
| ㉯ **월간 축을 되살린다** | `monthlySpendAmount` 필드를 다시 두고 등급은 그것으로 | 원래 설계로 되돌린다 |

⚠ 어느 쪽이든, **당장 빌드를 세우려고 메소드만 되살리실 때는**
`pointEarnedTotal` 을 0 으로 만들지 않게 해 주세요 — 그러면 월초마다
등급이 날아가는 것이 코드가 아니라 **데이터**로 남습니다.

## 2 `GET /internal/purchases/history` — 여전히 없습니다

08-28 요청 그대로입니다. 공개판(`/api/purchases`)은 `@CurrentConsumer` 로
로그인 세션에서 사용자를 꺼내는데, **Agent 는 브라우저가 아니라 서버라
쿠키도 JWT 도 없습니다.** `InternalWishlistController` 를 따로 만든 것과
같은 상황입니다.

```java
@GetMapping("/history")
public ResponseEntity<?> getPurchaseHistory(
        @RequestHeader("X-Internal-Service-Key") String key,
        @RequestParam Integer memberId,
        @RequestParam(defaultValue = "180") int lookbackDays) { ... }
```

⚠ **인자는 `memberId` 입니다.** `consumerId` 로 받으면 시드 회원 1005 가
10,001,005 로 둔갑해 항상 빈 결과가 옵니다(`wishlist`·`history` 에서 이미
두 번 겪은 함정입니다).

**없으면 막히는 것**: 소비주기 예측 · 취향 매칭 · 재구매 추천 — 도구 셋과
그 위의 기능 넷이 통째로 섭니다.

## 3 `InventoryService.move` 목적지 검사 — 여전히 없습니다

`stocks` 에 `UNIQUE(location_id)` 가 걸려 있어 **한 자리에 한 SKU** 인데,
지금 코드는 **같은 SKU 인지만** 봅니다. 다른 SKU 가 이미 있는 자리로 옮기면
INSERT 가 제약을 때려 **500** 이 납니다.

```java
if (stockRepository.findByLocationId(toLocationId).isPresent()) {
    throw new ResponseStatusException(HttpStatus.CONFLICT, "그 자리에 다른 상품이 있습니다");
}
```

리포지토리 쪽 한 줄도 같이 필요합니다:

```java
Optional<Stock> findByLocationId(String locationId);
```

⚠ 409 로 **이유를 말하는 것**이 요점입니다. 조용히 500 이 나면 시연 중에
어느 자리가 막힌 것인지 못 찾습니다.

## 곁 — 대체품 언더플로는 저희 요청보다 나은 방법으로 닫혔습니다

저희는 JPQL 에서 `CAST(p.priceKrw AS Long)` 을 씌우자고 했는데,
`ProductSearchService` 에서 **정렬 자체를 애플리케이션으로 올리셨더군요.**

```java
.sorted(Comparator.comparingInt((Product p) -> Math.abs(p.getPriceKrw() - price))
        .thenComparing(Product::getSkuId))
```

`Math.abs(int)` 는 부호 있는 계산이라 언더플로가 원리적으로 안 납니다.
DB 방언에 안 기대는 쪽이라 더 낫습니다 — 그대로 두시면 됩니다.
