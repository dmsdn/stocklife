> 다만 안 들어가면 아래 "이게 없으면 죽는 것" 칸의 기능이 데모에서 안 돕니다.

## ① `ProductSearchResponse` 에 `spec` 한 칸

`POST /api/products/by-skus` 가 `specRaw`(사람이 읽는 문자열)는 싣는데
`spec`(JSON)은 안 싣습니다. 엔티티에는 이미 있고, DTO 에서만 빠집니다.

```java
// dto/ProductSearchResponse.java  — 세 곳에 한 줄씩
private String spec;                                   // 필드 선언부
this.spec = product.getSpec();                         // 생성자
public String getSpec() { return spec; }               // 게터
```

**이게 없으면 죽는 것**: 도구 `compare_unit_price`(100ml당 가격 비교).
`specRaw` 는 "1.5L×6" 같은 자유 문자열이라 파싱이 필요하고, 그 파싱을
안 하기로 한 것이 우리 설계 결정입니다 — 대신 이미 정규화돼 있는 `spec`
(`{"quantity":{"primary":"volume_ml","value":9000}}`)을 그대로 받습니다.
**있는 것을 안 실어 주는 것이라 비용이 거의 0입니다.**

## ②③ `GET /internal/purchases/history`

회원의 **구매 시각 나열**이 필요합니다. 집계가 아니라 원장입니다.

```java
// controller/InternalPurchaseController.java
@GetMapping("/history")
public ResponseEntity<?> getPurchaseHistory(
        @RequestHeader("X-Internal-Service-Key") String key,
        @RequestParam Integer memberId) {
    try { internalServiceAuth.verify(key); }
    catch (SecurityException e) { return ResponseEntity.status(401).body(e.getMessage()); }
    return ResponseEntity.ok(purchaseService.getPurchaseHistoryByMemberId(memberId));
}
```

```java
// service/PurchaseService.java
@Transactional(readOnly = true)
public List<PurchaseHistoryResponse> getPurchaseHistoryByMemberId(int memberId) {
    return purchaseRepository.findHistoryByMemberId(memberId);
}
```

**새 쿼리가 아닙니다** — `findHistoryByMemberId` 와 `PurchaseHistoryResponse` 는
이미 있습니다. 내부 인증 창구만 없었습니다.

**`/internal/orders/frequent` 로 대신 못 하는 이유 둘**
1. 그쪽은 `orders` 를 읽는데 데모 데이터는 `purchases` 에 있습니다.
2. 응답이 집계(`purchaseCount`)라 **시각이 없습니다.** 구매 간격은 시각의
   나열에서만 나옵니다 — "3주쯤 됐으니 슬슬 떨어지셨을 것" 이 그 산물입니다.

> ⚠ **`consumerId` 가 아니라 `memberId` 를 받아야 합니다.** 공개판처럼
> `toMemberId` 변환을 태우면 시드 회원 `1005` 가 `10001005` 로 둔갑해
> 이력이 **항상 빕니다**(오류가 아니라 빈 배열이라 더 늦게 잡힙니다).

**이게 없으면 죽는 것**: 소비주기 예측(`predict_repurchase`) · 취향 매칭
(`match_preferences`) · 진입 브리핑의 "살 때 되신 것 2개" — 킬링 장면 3.

## ④ `find_substitutes` — UNSIGNED 언더플로 (1줄)

대체품 검색이 500 으로 떨어집니다.

```
ORDER BY ABS(price_krw - :basePrice)
```

`price_krw` 가 UNSIGNED 라 `싼 상품 - 비싼 기준가` 가 **음수가 아니라
언더플로**로 갑니다(MySQL: `BIGINT UNSIGNED value is out of range`).
`ABS` 는 그 뒤에 오므로 못 막습니다.

```sql
ORDER BY ABS(CAST(price_krw AS SIGNED) - CAST(:basePrice AS SIGNED))
```

## ⑤ `SessionCartItemResponse` 에 `cartItemId`

`GET /internal/cart/session` 의 항목에 `cartItemId` 가 없습니다. 그런데
수량변경·빼기는 그걸 받습니다. **그래서 "담기 → 수량 고치기" 사슬이
지금 안 이어집니다.**

`skuId` 로 대신 못 합니다 — 같은 상품이 여러 줄일 수 있습니다.

지금 우리 쪽은 이 부재를 **응답에 말로 실어** 보냅니다("이 목록에는
cart_item_id 가 없으니 앱에서 직접 수정하도록 안내하라"). 조용히 비워
두면 LLM 이 `sku_id` 를 `cart_item_id` 로 넘겨 **엉뚱한 줄을 지웁니다.**

## ⑥ `/internal/wishlist`

찜 목록 조회 창구가 없습니다. 공개 API 는 세션 쿠키를 요구하는데
Agent 는 서버라 쿠키가 없습니다. `/internal/cart/session` 과 같은 꼴로
`consumerId` 를 받는 내부판 하나면 됩니다.

**이게 없으면 죽는 것**: 도구 `get_wishlist` — "찜한 것 중에 지금 행사
하는 거 있어요?" 가 답을 못 합니다.
