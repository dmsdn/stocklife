## ① `ProductSearchResponse` 에 `spec` 한 칸

`POST /api/products/by-skus` 가 `specRaw`(사람이 읽는 문자열)는 싣는데
`spec`(정규화된 JSON)은 안 싣습니다. 엔티티에는 이미 있고 DTO 에서만 빠집니다.

```java
// product/dto/ProductSearchResponse.java — 세 곳에 한 줄씩
private String spec;                         // 필드
this.spec = product.getSpec();               // 생성자
public String getSpec() { return spec; }     // 게터
```

**이게 없으면 죽는 것**: 도구 `compare_unit_price`(100ml당 가격 비교).

`specRaw` 는 `"1.5L×6"` 같은 자유 문자열이라 파싱이 필요한데, **그 파싱을
안 하기로 한 것이 저희 설계 결정**입니다(상류에 이미 구조가 있는데 하류에서
문자열을 되파싱하면 정보가 줄기만 합니다). 대신 이미 정규화돼 있는
`spec`(`{"quantity":{"primary":"volume_ml","value":9000}}`)을 그대로 받습니다.
**있는 것을 안 실어 주는 것이라 비용이 거의 0입니다.**

## ② `GET /internal/purchases/history`

회원의 **구매 시각 나열**이 필요합니다. 집계가 아니라 원장입니다.

```java
// purchase/controller/InternalPurchaseController.java
@GetMapping("/history")
public ResponseEntity<?> getPurchaseHistory(
        @RequestHeader("X-Internal-Service-Key") String key,
        @RequestParam Integer memberId) {
    try { internalServiceAuth.verify(key); }
    catch (SecurityException e) { return ResponseEntity.status(401).body(e.getMessage()); }
    return ResponseEntity.ok(purchaseService.getPurchaseHistoryByMemberId(memberId));
}
```

```java
// purchase/service/PurchaseService.java
@Transactional(readOnly = true)
public List<PurchaseHistoryResponse> getPurchaseHistoryByMemberId(int memberId) {
    return purchaseRepository.findHistoryByMemberId(memberId);
}
```

**새 쿼리가 아닙니다** — `findHistoryByMemberId` 와 `PurchaseHistoryResponse` 는
이미 있습니다. 내부 인증 창구만 없었습니다.

**`/internal/orders/frequent` 로 대신 못 하는 이유 둘**

1. 그쪽은 `orders` 를 읽는데 데모 데이터는 `purchases` 에 있습니다.
2. 응답이 집계(`purchaseCount`)라 **시각이 없습니다.** 구매 간격은 시각의
   나열에서만 나옵니다 — *"3주쯤 됐으니 슬슬 떨어지셨을 것"* 이 그 산물입니다.

**이게 없으면 죽는 것**: 소비주기 예측(`predict_repurchase`) · 취향 매칭
(`match_preferences`) · 진입 브리핑의 "살 때 되신 것" — **킬링 장면 3 전체**.

## ③ `find_substitutes` 500 — UNSIGNED 언더플로 (2줄)

대체품 검색이 **항상 500** 입니다.

```
Data truncation: BIGINT UNSIGNED value is out of range
                 in '(storeflow_db.p1_0.price_krw - 40690)'
```

`price_krw` 가 UNSIGNED 라 **「싼 상품 − 비싼 기준가」가 음수가 아니라
언더플로**로 갑니다. `ABS` 는 그 **뒤**에 오므로 못 막습니다.

```java
// product/repository/ProductRepository.java — 두 질의 모두
// findAlternativesByKeyword · findAlternativesByPriceBand
- ORDER BY ABS(p.priceKrw - :originalPrice) ASC, p.skuId ASC
+ ORDER BY ABS(CAST(p.priceKrw AS Long) - :originalPrice) ASC, p.skuId ASC
```

컬럼을 부호 있는 타입으로 올리면 이후 산술이 전부 signed 로 갑니다.
(`:originalPrice` 는 이미 int 라 안 건드려도 됩니다.)

**이게 없으면 죽는 것**: 품절 대체 안내 — *"그건 다 나갔는데 이건 어떠세요"*.

## ④ `SessionCartItemResponse` 에 `cartItemId`

`GET /internal/cart/session` 의 항목에 `cartItemId` 가 없습니다. 그런데
수량변경(`PATCH /internal/cart/{cartItemId}`)과 빼기는 그걸 받습니다.
**그래서 「담기 → 수량 고치기」 사슬이 끊깁니다.**

// cart/dto/SessionCartItemResponse.java
private Long cartItemId;                                  // 필드
this.cartItemId = item.getCartItemId();                   // 생성자
public Long getCartItemId() { return cartItemId; }        // 게터

⚠ 이게 없는 동안 저희 쪽은 그 부재를 응답에 **말로 실어** 보냈습니다
("이 목록엔 cart_item_id 가 없으니 앱에서 직접 수정하도록 안내하라").
조용히 비워 두면 LLM 이 `sku_id` 를 `cart_item_id` 로 넘겨 **엉뚱한 줄을
지웁니다.** 들어가면 그 우회를 걷어냅니다.

## ⑤ `GET /internal/wishlist`

공개 `/api/wishlist` 는 `@CurrentConsumer` 로 사용자 JWT 를 요구합니다.
Agent 는 브라우저가 아니라 **서버**라 쿠키가 없어서 500 이 납니다
(`IllegalStateException: 인증 토큰이 없습니다`).

```java
// wishlist/service/WishlistService.java
@Transactional(readOnly = true)
public List<WishlistItemResponse> getWishlistByMemberId(int memberId) {
    return wishlistRepository.findWishlistByMemberId(memberId);
}
```

```java
// wishlist/controller/InternalWishlistController.java  (신규)
@RestController
@RequestMapping("/internal/wishlist")
public class InternalWishlistController {
    // … 생성자 주입: WishlistService, InternalServiceAuth

    @GetMapping
    public ResponseEntity<?> getWishlist(@RequestHeader("X-Internal-Service-Key") String key,
                                         @RequestParam Integer memberId) {
        try { internalServiceAuth.verify(key); }
        catch (SecurityException e) { return ResponseEntity.status(401).body(e.getMessage()); }
        return ResponseEntity.ok(wishlistService.getWishlistByMemberId(memberId));
    }
}
```

**이게 없으면 죽는 것**: 도구 `get_wishlist` — *"찜한 것 중에 지금 행사하는
거 있어요?"* 와 진입 브리핑의 찜 항목.

⚠ **인자가 `consumerId` 가 아니라 `memberId` 입니다.** 이유는 §7.

## ⑥ `InventoryService.move` — 목적지 검사가 한 겹 모자랍니다 (17줄)

이동 API 가 **500** 을 냅니다. 부르는 쪽에서는 서버가 고장난 것처럼 보이는데,
실제로는 요청이 규칙을 어긴 겁니다.

`stocks` 에 **`UNIQUE KEY uq_stk_location (location_id)`** 이 걸려 있습니다 —
**한 자리에 한 SKU** 가 이 세계의 불변식입니다(매대 한 칸 = 상품 하나).
그런데 지금 검사는 *"목적지에 **같은 SKU** 의 재고가 있나"* 만 봅니다.
다른 SKU 가 이미 쓰는 자리로 옮기면 그 검사를 통과했다가 `INSERT` 에서
제약 위반으로 터집니다.

```java
// inventory/service/InventoryService.java — move() 안, 기존 검사 바로 뒤
if (stockRepository.findByLocationId(toLocationId).isPresent()) {
    throw new IllegalStateException(
        "대상 위치가 이미 다른 상품에 쓰이고 있습니다(한 자리에 한 SKU). locationId="
        + toLocationId);
}
```

```java
// inventory/repository/StockRepository.java
Optional<Stock> findByLocationId(String locationId);
```

컨트롤러가 `IllegalStateException` 을 이미 **409** 로 매핑하고 있어서,
이 한 겹만 있으면 **500 이 409 + 이유**로 바뀝니다.

**이게 없으면 죽는 것**: 기능이 죽는 건 아닙니다. 다만 시연 중 자리 이동을
쏘다가 500 이 나면 **원인을 그 자리에서 못 찾습니다.** 저희는 이걸로 한참
헤맸습니다.

## ⑦ ⚠ 같은 함정을 두 번 밟았습니다 — `memberId` vs `consumerId`

**②와 ⑤ 둘 다, 내부 창구는 `memberId` 를 그대로 받아야 합니다.**

공개판 서비스들은 `Member.toMemberId(consumerId)` 변환을 태웁니다.
그런데 Agent 는 세계 시드 회원(`1001~11000`)을 **`member_id` 축으로** 다룹니다.
내부 창구를 공개판처럼 `consumerId` 로 받아 변환을 태우면:

```
Agent 가 1001 을 보냄 → toMemberId → 10,001,001 → 그런 회원 없음 → []
```

**404 도 500 도 아니고 200 에 빈 배열이 옵니다.** 그래서 제일 안 잡힙니다 —
창구는 살아 있고 로그도 깨끗한데 에이전트만 "이력이 없네요"라고 말합니다.
②에서 한 번 밟고, ⑤를 만들 때 하마터면 또 밟을 뻔했습니다.

> 규칙으로 적어 두면 좋겠습니다: **`/internal/**` 중 세계 시드를 읽는 창구는
> `memberId` 를 받는다.** (장바구니처럼 `consumer` 테이블을 참조하는 것은
> 그대로 `consumerId` 가 맞습니다 — 축이 다릅니다.)

## 부록 — 저희 쪽에서 이미 감당한 것 (요청 아님)

같은 종류의 어긋남인데 **에이전트 쪽에서 고칠 수 있어서** 고친 것들입니다.
백엔드는 안 건드렸습니다. 혹시 같은 증상을 다른 데서 보시면 참고가 될까 해서
적어 둡니다.

| 무엇 | 어긋남 |
|---|---|
| `get_change_events` | 파라미터 이름이 `sku_ids/within_hours` ↔ `skuIds/hours` → **400**. 기능은 멀쩡했는데 "창구가 없나" 하고 엉뚱한 데를 봤습니다 |
| 〃 | 백엔드가 `Instant.now()` 로 창을 잡는데 저희 세계의 「지금」은 **2026-08-08**(DES 스냅샷)입니다. 그래서 "최근 24시간"이 **영원히 0건**이었습니다. 저희 쪽에서 그 차이만큼 `hours` 를 벌려 보정합니다. 세계가 벽시계를 따라잡으면 보정이 저절로 사라집니다 |
| `get_inventory`·`search_products` | camelCase 를 그대로 흘려 값이 **조용히 `None`** 이 됐습니다. 경계에서 한 번에 변환하도록 고쳤습니다 |
| `get_session_cart` | `/api/sessions/{id}/cart` 는 없습니다(404). `/internal/cart/session?consumerId=` 로 갈아탔습니다 — 이름은 session 인데 인자는 회원입니다 |
| `get_popular_products` | 빈 문자열을 보내면 안 되고 **파라미터를 빼야** 했습니다 |
