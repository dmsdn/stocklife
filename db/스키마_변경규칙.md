## 🔴 무조건 유지 — 바꾸면 AI 기능이 죽습니다

| 대상 | 지켜야 할 것 | 어기면 깨지는 것 |
|---|---|---|
| `locations.tier_role` | ENUM `PICK` / `BULK` | 매대(집는 칸)와 그 위 예비 재고의 구분이 사라짐 → **"몇 분 뒤 채워집니다" 예측 불가** |
| `locations.floor_no` · `x` · `y`<br>`map_cells` PK(floor_no,x,y) | 좌표 3종과 격자 기본키 | 매장 내 길안내·위치 추정의 유일한 입력이 사라짐 |
| `shelf_configs.min_qty` | 존재 + "이 수량 밑으로 내려가면 보충" 의미 | 보충이 시작된 시점을 알 수 없어 소요 시간 측정 불가 |
| `shelf_events.event_type` | ENUM **8종의 철자 그대로**<br>`SALE` `BELOW_PAR` `TASK_QUEUED` `TASK_STARTED` `ITEM_CONFIRMED` `STOCKOUT` `RESTOCK_IN` `MOVE` | 학습·조회가 이 문자열로 걸러집니다. 이름이 바뀌면 **에러 대신 결과 0건**이 나옵니다 |
| `consumer_events.event_type` | ENUM **6종**<br>`SCAN_ADD` `SCAN_REMOVE` `SEARCH` `VIEW` `LIST_EDIT` `PURCHASE` | 위와 동일 |
| 두 이벤트의 `occurred_at` | `TIMESTAMP(3)` — **밀리초 보존**, 값은 "실제 발생 시각"(기록 시각 아님) | 초 단위로 반올림되면 분 단위로 끝나는 보충의 분포가 뭉개져 예측이 부정확해짐 |
| `consumer_events.session_id` / `member_id` | 앞은 NOT NULL, 뒤는 **NULL 허용** | 비회원 세션이 사라지면 로그인한 사람에게만 AI가 동작 |
| `SCAN_ADD` 이벤트의 `location_id` | 반드시 채울 것 | **스캔이 곧 사용자의 위치**입니다. 비면 매장 내 길안내가 불가능 |
| `products.sku_id` · `barcode` | 재사용 금지(리뉴얼은 새 SKU), `barcode` UNIQUE | 과거 구매 이력이 다른 상품과 섞여, 없는 재구매 패턴을 학습하게 됨 |
| `products.lifecycle_status` | 단종은 **행 삭제가 아니라 상태 전환** | 위와 동일 + "단종됐어요, 대신 이건" 기능 불가 |
| `stocks.location_id` UNIQUE | 한 칸 = 한 상품 | 재고와 이벤트의 (상품, 위치) 해석이 무너짐 |
| `purchases`의 `member_id`·`sku_id`·`purchased_at` | 3종 유지 | 소비 주기 학습의 최소 축 — **개인화 기능 8개**가 전부 여기 매달려 있음 |
| `products.spec` JSON의 `quantity.primary` · `quantity.value` | 키 이름과 의미 고정 | 단위가격 비교의 분모가 사라짐(어느 쪽이 이득? · 고민 개입 · 대체 추천) |
| `products.category_l1` · `category_l2` + 플래그 4종<br>(`is_refrigerated` `is_frozen` `is_alcohol` `is_fresh`) | **컬럼 존재**(값 목록은 🟡) | AI가 조건으로 변환할 대상이 없어져 추론으로 흘러가고, 그러면 틀립니다 |

### 동작 계약 (스키마가 아니라 코드 쪽 약속)

1. **이벤트는 append-only** — 수정·삭제하지 않습니다.
2. **`BELOW_PAR`는 전이일 때만 발행** — 임계 아래로 "내려가는 순간" 한 번. 매 판매마다 발행하면
   "언제 부족해졌는가"가 사라집니다. 재고를 바꾸는 것과 **같은 트랜잭션**에서 발행해 주세요.
3. **재고 갱신은 백엔드 한 경로로만** — AI 서버는 DB에 쓰지 않습니다.
4. **행동 이벤트는 발생 즉시 건별 전송** — 결제 시점에 몰아 보내면, 사용자가 진열대 앞에서
   고민하는 **그 순간**이 지난 뒤에 도착해 개입이 불가능해집니다.

## 🟡 바꿔도 되지만 알려주세요 — ML 쪽 재생성·재학습이 따라옵니다

| 대상 | 조건 |
|---|---|
| 카테고리 **값 목록** (대분류 12 · 소분류 약 60) | 바꾸면 AI 프롬프트와 상품 생성기를 함께 갱신해야 합니다 |
| ENUM에 **새 타입 추가** | **맨 끝에만** 추가해 주세요(중간 삽입은 기존 행의 의미가 밀립니다). 추가 시 알려주시면 반영합니다 |
| 타입 **확장** (`VARCHAR` 길이 ↑, `TINYINT`→`SMALLINT`) | 무손실 확장은 괜찮습니다. 축소는 🔴 |
| 테이블·컬럼 **이름 변경** | 우리 쿼리를 전부 고쳐야 하므로 사전 공유 필요 |
| 기존 인덱스 삭제 | `uq_stk_location` 등은 계약이자 성능입니다(참고: 이 인덱스는 외래키가 물고 있어 삭제 자체가 막힙니다) |
| `price_krw` 단위·타입 | 가격이 규격과 정합해야 단위가격 비교가 성립합니다 |

## 🟢 완전 자유 — 통보도 필요 없습니다

- **컬럼 추가** — `created_at` / `updated_at`, `sort_order`, `is_display`, `description`,
  `thumbnail_url`, 관리자용 메타 등 **무엇이든**. 우리는 필요한 컬럼만 이름으로 읽습니다.
- **테이블 추가** — 장바구니·주문·결제·쿠폰·배너 등 백엔드 고유 도메인 전체.
- **백엔드 고유 영역 전부** — 로그인·인증·회원 계정·결제. 우리 스키마는 여기를 아예 건드리지
  않습니다(`members`는 페르소나·가구 규모만 담은 별도 테이블입니다).
- 인덱스 **추가**, 뷰·프로시저, 기본값·주석, 문자셋 설정(utf8mb4만 유지).
- `name` · `brand` · `image_url`의 **문자열 내용**, 시드 재적재 시점.

## 왜 이렇게까지 하나 (한 문단)

AI 파이프라인의 고장은 **에러를 내지 않습니다.** 이벤트 타입 철자가 하나 바뀌면 예외가 나는 게
아니라 조회 결과가 0건이 되고, 밀리초가 잘리면 예측이 조금씩 빗나갈 뿐 로그는 깨끗합니다.
그래서 "문서로 부탁"하는 대신 **실행 가능한 검사**로 만들어 두었습니다.
질문이 생기면 언제든 물어봐 주세요 — 🔴 목록도 이유가 없어지면 언제든 바꿀 수 있습니다.
