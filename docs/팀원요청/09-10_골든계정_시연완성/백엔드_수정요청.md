# 골든 계정 시연 — Backend 담당자 인계

2026-09-10. ljk_instant `51270be`에 구현·배포한 변경이다. branch_ljk의 Backend는 수정하지 않았다. 팀 최신 코드와 아래 기능을 대조해 필요한 부분을 반영한다. 폴더 전체를 오라클로 덮어쓰지 않는다.

## 실제 문제와 처리

AI purchases 이력은 있어도 orders/order_item이 비어 있어 구매내역 화면이 비었다. 전용 계정의 표시용 역사 주문을 JPA로 멱등 적재하고 정상 가상 결제를 따로 실행한다. cart_item의 과거 consumer_id 열은 현재 엔티티에서 쓰지 않으므로 반드시 cart_group 소유자를 조인한다.

재고 이벤트를 커밋 전에 SSE로 보내면 Agent가 이전 재고를 읽을 수 있다. EventBroadcastService에서 트랜잭션 afterCommit 이후에 보내며 롤백 때는 보내지 않는다. 자발형 채팅 저장과 함께 NotificationService로 AI_PROACTIVE 알림을 저장한다.

## API와 배포 설정

모든 `/api/demo` 요청은 기존 JWT로 consumerId를 읽고 **consumerId=2002 + phone_number=01090000001 + enable flag**를 검증한다. 다른 환경의 숫자 2002만 믿지 않는다.

| 메서드/경로 | 동작 |
|---|---|
| GET `/api/demo` | 전용 계정의 목록·주문·알림 현황 |
| POST `/api/demo/prepare` | 24개 합성 이력의 표시용 주문을 중복 없이 준비, 네 ACTIVE 장면과 예정 행사 준비 |
| POST `/api/demo/session` | body groupId가 본인 소유 ACTIVE 시연 목록일 때 새 채팅 생성 |
| POST `/api/demo/entry` | 본인 sessionId에 첫 SCAN_ADD |
| POST `/api/demo/hesitation` | 본인 sessionId에 두 SKU VIEW 3회 |
| POST `/api/demo/stockout`, `/restock` | 지정 SKU만 정상 InventoryService 경로로 매대 0 → 12 |
| POST `/api/demo/move` | 지정 SKU를 같은 층의 빈 유효 매대로 이동, shelf_configs 위치도 함께 갱신 |
| POST `/api/demo/checkout` | 지정 결제 목록을 OrderService로 가상 결제, 보유 포인트 최대 100P 사용 |
| POST `/api/demo/repurchase` | 내부 인증된 Agent 후보 API로 세션 밖 추론 후 전용 DB 알림 생성 |
| POST `/api/demo/promotion` | 실제 예정 행사 시각을 한국시간으로 안내. 당일 기존 안내는 중복 생성 없이 갱신 |

장면 body는 `{groupId, sessionId}`이며 신원을 body에서 받지 않는다. prepare/repurchase/promotion은 빈 body로 호출 가능하다. 지정 SKU 범위 및 다른 소비자의 cart_group 소유 여부를 검사한다. 일반 계정이나 전체 RDS 초기화용 API가 아니다.

배포 설정: `STOREFLOW_GOLDEN_DEMO_ENABLED=true`, `STOREFLOW_GOLDEN_REMINDERS_ENABLED=true`; Agent는 `STOREFLOW_LIVE_CLOCK=1`. 기존 RDS 연결·내부 인증키는 유지한다. 후보 서버에서는 reminders flag를 끈다. 기본값은 false다.

배포 JDBC serverTimezone=Asia/Seoul, JVM UTC, RDS session UTC를 실측했다. DATETIME과 TIMESTAMP를 JdbcTemplate Timestamp로 왕복해 복사하면 날짜가 달라졌다. 역사 주문은 정상 JPA 경로로 저장한다. 기존 합성 주문 24개는 이번 계정/주문 ID로 범위를 제한해 이미 교정했다. 다른 DB에 원시 UPDATE를 일괄 적용하지 않는다.

## 검증과 경계

Backend build 성공, 17개 테스트 통과·기존 1개 생략. 공개 API에서 역사 주문 24개 시각 일치·재준비 중복 0, 정상 주문 2건·포인트·등급·재입고·행사·자발형 DB 저장과 SSE를 확인했다. 가상 결제이며 외부 PG 거래는 없다. 매장 밖 알림은 앱 DB 보관까지다. 쿠폰 발급/사용 서버나 OS Web Push/FCM 구현으로 소개하지 않는다.
