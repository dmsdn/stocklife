# 골든 계정 시연 — Frontend 담당자 인계

2026-09-10. ljk_instant `51270be`에 구현·배포했다. branch_ljk의 frontend 소스는 수정하지 않았다. 팀 최신 프론트와 아래 기능을 비교해 적용하며 전체 폴더 교체나 기존 담당자 변경 삭제를 하지 않는다.

## 변경 파일과 동작

| 파일 (frontend 기준) | 필요한 동작 |
|---|---|
| `app/(main)/demo/page.tsx` 신규 | 인증된 GET /api/demo 현황, 장면별 새 채팅, 준비·첫 스캔·품절·보충·이동·망설임·가상 결제 버튼. ACTIVE 시연 목록만 표시 |
| `app/(main)/mypage/page.tsx` | consumerId=2002일 때 ‘골든 시연 열기’ 링크. 실제 권한은 백엔드에서 별도 검증 |
| `app/(main)/notifications/page.tsx` | DB 알림을 5초마다 갱신. AI_PROACTIVE/REPURCHASE를 리브로, POINT/GRADE/PROMOTION을 혜택으로 분류. 동일한 로컬 자발형/DB 문구 중복 표시 방지. 계정 변경 도중 도착한 이전 응답 폐기 |
| `lib/use-unread-notifications.ts` | 5초 갱신·인증 변경 재조회. 비동기 응답의 토큰이 현재 로그인 토큰과 같을 때만 배지 갱신 |

기존 AiChatBody를 재사용한다. `sessionIdOverride`로 열린 대화를 고정하고 `onSessionReady` 전에는 장면 실행을 막는다. 전역 활성 대화를 바꾸더라도 다른 창의 리스트로 명령이 새지 않게 한 기존 계약을 유지해야 한다. 선행 통합 내용은 09-09 채팅 리스트/상세 링크/리브 추천 요청서를 함께 참고한다.

재입고는 품절 준비 → 채팅으로 관심 등록 → 보충 순서다. 위치 이동은 채팅으로 현재 리스트를 조회한 뒤 실행한다. 결제 후 완료 리스트는 그대로 보관하고 ‘시연 목록 준비’로 다음 ACTIVE 결제 리스트를 만든다. 시연 화면의 가상 결제는 보유 포인트를 최대 100P 사용한다고 버튼에 표시한다.

## 백엔드와 연결할 계약

- `/api/demo`와 장면 API는 기존 `apiFetch`로 호출하며 JWT를 사용한다. body는 `{groupId,sessionId}`다.
- 주문과 알림 날짜에 `Z` 또는 오프셋이 포함된다. 표준 Date 파싱을 사용한다. 구형 알림 문자열의 오프셋이 없을 때만 현재 배포의 UTC 형식으로 보완한다.
- 알림 linkUrl을 그대로 상세 링크로 사용한다. 주문 링크는 `/mypage/orders/{id}`, 제품은 `/product/{skuId}`, 채팅은 `/ai?session=...`다.
- DB 저장된 자발형 알림과 예전 localStorage 알림을 합칠 때 같은 문구는 한 번만 보인다. DB는 최대 480자 요약이므로 긴 동일 문구의 접두사도 비교한다.
- 조회 중 로그아웃·계정 변경이 일어나면 이전 계정 결과를 보여주지 않는다.

## 검증과 시연 범위

Linux production build 성공, 프론트 통합 35개·동선 10개 검사 통과. 공개 API와 프론트가 구독하는 SSE에서 실제 메시지를 확인했다. 사용자가 컴퓨터 유즈를 금지해 최종 브라우저 조작·육안 검증은 수행하지 않았다. 빌드와 API 결과를 화면 실측 결과로 바꾸어 보고하지 않는다.

현재 계정 주문 26건·알림 16건·BRONZE·1,376P, 다음 결제 목록 38을 준비했다. 구매내역 기본 기간은 최근 3개월이므로 전체 반복 이력을 보이려면 2026년 5월~9월로 넓힌다. 쿠폰 목업과 OS 잠금화면 푸시는 실제 구현된 것으로 소개하지 않는다.
