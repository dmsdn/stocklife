# 채팅 리스트·상세 링크·리브 추천 수정 요청 — 프론트

작성: 2026-09-09. 이번 요청의 세 기능만 다룹니다.

## 적용 상태와 범위

- `ljk_instant`: Agent `a273db7`, Backend/frontend `eb8d180`으로 구현·검증하고 로컬 반영했습니다. 원격에 게시하지 않았습니다.
- `branch_ljk`: Agent 변경만 `7ec1cc4`로 이관했습니다. 백엔드·프론트 소스는 수정하지 않았습니다. 이 문서는 담당자에게 전달할 요청사항입니다.
- 비교 기준: 오라클 수정 전 `98ee037`, 팀 브랜치 수정 전 `5340d0b`. 부록은 **이번 기능 변경만** 담은 오라클 기준 diff입니다. 팀 브랜치 전체 파일을 오라클 파일로 교체하지 마세요. 기존 담당자 구현을 유지하면서 해당 동작을 반영해야 합니다.
- Agent만 교체하면 프론트의 세션 혼선이나 홈 추천이 모두 해결되지는 않습니다. 아래 백엔드·프론트 계약을 함께 적용한 후 통합 확인해야 합니다.
- DB 스키마 변경·초기화는 없습니다. 기존 `ChatSession.groupId`를 사용합니다. RDS에 테스트 장바구니 쓰기는 하지 않았습니다.

## 공통 원인과 동작

1. 브라우저의 전역 활성 채팅 ID가 다른 창에서 바뀌면 메시지가 다른 채팅으로 전송됐습니다. 리스트 화면 진입 시 기존 채팅의 groupId 일치 검사도 빠져 있었습니다.
2. 백엔드는 채팅의 groupId를 저장하지만 Agent 요청에는 전달하지 않았고, Agent의 담기 요청도 groupId를 생략해 기본 장바구니로 들어갔습니다.
3. 수정 후 흐름은 `화면에 고정한 sessionId → 서버 소유권 검사 → 저장된 ChatSession.groupId → Agent groupId → 요청별 문맥 → /internal/cart의 groupId`입니다.
4. 일반 채팅에 활성 리스트가 여러 개면 Agent가 대상 리스트를 확인합니다. 이름으로 다른 리스트를 요청하면 실제 목록에서 group_id를 조회해 명시합니다. 삭제·완료·타인 리스트에는 쓰지 않고 다른 기본 리스트로 대신 담지도 않습니다. 수정·삭제 역시 선택 리스트의 항목인지 검사합니다.
5. Agent가 실제 조회한 리스트 ID와 주문 ID를 답변에 Markdown 링크로 붙입니다. 구매 학습 데이터의 basket_id를 주문 ID로 바꾸지 않습니다.
6. 홈 추천은 현재 출하된 `predict_repurchase`와 `match_preferences` 결과를 사용합니다. 가격·상품명·이미지는 실제 상품 조회 결과이며 사유는 재구매 간격 또는 구매 분야를 근거로 표시합니다. 진행 중 T17 신규 모델을 교체하거나 LLM을 매번 호출하는 기능이 아닙니다. 이력이 부족한 취향 후보는 일반 구매 경향임을 표시합니다.

### 링크 표현

Agent 답변 예시: `[주말 장보기](/saved/11)`, `[9월 9일 구매내역](/mypage/orders/45)`.
기존 Markdown 렌더러에서 Next Link로 표시하고 클릭 시 AI 패널을 닫아 상세 화면을 보여줍니다. 허용 경로는 양의 정수 ID를 가진 `/saved/{id}`, `/mypage/orders/{id}`, `/mypage/receipts/{id}`뿐입니다. 외부 URL·스크립트·임의 경로·쿼리 문자열은 링크로 만들지 않습니다. 영수증 경로 허용은 렌더러 범위이며 Agent가 학습 basket_id로 영수증 링크를 생성하는 것은 아닙니다.

현재 구현은 조회된 내역을 답변 아래 ‘관련 내역 바로가기’ 링크 목록으로 제공합니다. 본문의 모든 일반 텍스트를 자동으로 상세 링크로 변환하지는 않습니다. 저장된 답변을 다시 열어도 같은 Markdown 링크가 표시됩니다.

### 기존 코드와 통합 시 주의

오라클 98ee037에는 이전 로그인/로그아웃 계정 격리 수정과 `AUTH_CHANGED_EVENT` 등이 포함되어 있습니다. 팀 5340d0b의 프론트는 이 부분이 다릅니다. 기존 auth 이벤트와 세션 초기화 흐름을 확인해 동등하게 연결해야 하며, 부록만 무조건 적용하면 import나 테스트 기반 파일이 없을 수 있습니다. 이번 변경을 위해 기존 장보기 동선·지도·상품 상세·포인트 기능을 교체할 필요는 없습니다.

전역 localStorage는 최근 채팅 선택용으로 유지할 수 있습니다. 실제 전송·첨부는 각 화면에 고정한 ID로 해야 합니다. 서버의 세션 메타데이터 확인 전에는 전송을 열지 마세요.

## 검증 근거와 한계

- 오라클: Agent 35개 통과, 프론트 45개 통과, 백엔드 12개 통과·1개 제외. 프론트 프로덕션 빌드와 백엔드 build 성공.
- branch_ljk 이관 후 해당 브랜치에 있는 Agent 검사 31개 재실행 통과. 오라클 전용 integration_http_check 4개는 팀 브랜치에 없으므로 팀 검사 합계에 포함하지 않았습니다.
- Agent의 도구 24개 스키마 검사 통과. 테스트는 요청 문맥·권한·계약·회귀를 검증하며 실제 LLM이 모든 자연어를 올바르게 이해한다는 보장은 아닙니다.
- 브라우저 API 목업 검사: 두 탭 전송 A→B→A, 다른 리스트 진입 시 새 채팅 생성, 목록/주문 상세 링크 이동, 추천 사유 표시 통과. 이 검사는 RDS 쓰기를 하지 않았습니다.
- 별도 읽기 검증: 기존 백엔드를 통한 RDS 조회와 실제 출하 추론에서 추천 8개를 얻었고 재구매·취향 두 출처 및 이미지 8개를 확인했습니다.
- 배포 서버 반영과 새 코드 전체를 통한 실제 LLM→장바구니 쓰기 E2E는 시행하지 않았습니다. 팀 코드 반영 후 위 시나리오의 통합 확인이 필요합니다.
- warehouse의 학습 중 Agent는 이번에 덮어쓰지 않았습니다. 이후 handoff.py 이관 시 이 문서와 a273db7의 요청별 리스트 문맥·링크·추천 경로를 비교해 보존해야 합니다. 일반 파일명세/교재의 전면 갱신은 이번 요청 범위 밖입니다.
