# StoreFlow Simulation

React + TypeScript + Phaser 3로 만든 걸어다니는 매장 시뮬레이션 초기 골격.
storeflow_db 스키마(`schema_v2.sql`)와 도면 3장(1F/2F/3F)을 기준으로 만들어졌다.

## 실행

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:5173` 접속.

- 방향키: 누르고 있으면 계속 이동 (뗄 때까지 반복 이동, 한 번 누르면 한 칸)
- 매대 또는 엘리베이터/에스컬레이터 칸 클릭: 같은 층이면 A* 최단경로로 자동 이동, 다른 층이면
  "엘리베이터/에스컬레이터 중 선택" 팝업이 뜨고 선택한 수단으로 실제로 이동수단을 타고 이동.
  (그냥 빈 통로 클릭은 아무 반응 없음 — 매대/시설물을 클릭했을 때만 이동)
- 매대 바로 옆에서 스페이스바: 그 매대에 진열된 상품 팝업 (상품별로 "담기" 버튼으로 장바구니에 추가)
- 에스컬레이터 칸 위에서 스페이스바: 그 에스컬레이터가 향하는 방향(상행/하행)으로 한 층 이동
- 엘리베이터 칸 위에서 스페이스바: 이동할 층을 고르는 팝업
- 우클릭 드래그: 화면 이동
- 마우스 휠: 줌
- 상단바 🏠 층 표시(▾ 클릭 시 B1/1F/2F/3F 드롭다운): "보기 층"만 전환 (캐릭터는 실제로 이동수단을 타야만 층이 바뀜 — 다른 층을 미리보기만 하는 상태에서는 화면에 캐릭터가 보이지 않음)
- 상단바 🛒 버튼: 장바구니 팝업 — 담긴 상품 확인/삭제, "구매하기"로 결제(잔액 차감), 구매 내역에서
  "환불하기"로 환불(잔액 복구 + 재고 원복)
- 상단바 🤖💬 AI Chat 버튼: 채팅 팝업 (지금은 스텁 — 실제 AI 응답 아님, 아래 참고)

## 지금까지 구현된 것

- 도면 3장을 픽셀 단위로 분석해서 만든 실제 매장 좌표 데이터 (`src/data/floor{1,2,3}.json`) — 19개 존, 1,684개 선반 칸
- 지하 1층(B1)은 임시 창고 층으로 별도 추가 (`src/data/floor0.json`) — 실제 도면 없이 격자 하나로 단순 구성한 placeholder, 4×14 랙 56칸
- Phaser 씬이 이 데이터를 읽어 실제 도면과 같은 배치로 매대를 그림
- A* 그리드 경로탐색 (`src/game/pathfinding/astar.ts`) — 매대 클릭 시 자동 이동, 키보드 이동과 로직 공유
- 층 전환 시 씬을 파괴하지 않고 데이터만 교체 (`StoreScene.loadFloor`)
- 좌표를 API가 아니라 로컬 JSON에서 읽지만, `src/api/locations.ts` 하나만 갈아끼우면 실제 백엔드로 전환되는 구조 (프론트 나머지 코드는 영향 없음)
- **편의시설(엘리베이터/에스컬레이터/화장실/정수기)**: 각 층 JSON의 `facilities` 배열
  (`family_restroom`, `restroom_male`, `restroom_female`, `water`, `escalator_up`,
  `escalator_down`, `elevator`)로 표현, 아이콘 + 한글 이름표로 렌더링. **주의: 원본 도면에는
  이 시설물들이 표시되어 있지 않아서, 좌표는 실제 도면 근거 없이 오른쪽 여백에 제가 임의로
  배치한 placeholder입니다.** 나중에 실제 도면(또는 실측)에서 좌표를 받으면
  `gen_floor_json2.py`의 `ESCALATORS_BY_FLOOR`/`RESTROOMS_COMMON`만 바꿔서 다시 생성하면 됩니다.
- **에스컬레이터는 방향이 있는 별개의 시설물**: 1층엔 상행(`escalator_up`)만, 2층엔 상행·하행
  둘 다, 3층엔 하행(`escalator_down`)만 배치. 상행 칸에서 스페이스바를 누르면 위층으로,
  하행 칸에서 누르면 아래층으로 이동. B1은 에스컬레이터 없이 엘리베이터만 있음.
- **매대 진열 상품 팝업**: 매대 옆에서 스페이스바를 누르면 그 매대(location_id)에 진열된
  상품 목록이 뜬다 (`src/api/products.ts`). **주의: 실제 상품/재고 데이터가 아니라
  location_id를 시드로 결정적으로 생성한 가짜 상품입니다** (같은 매대는 새로고침해도 항상 같은
  목록). 실제 상품 데이터가 준비되면 `fetchProductsAtLocation` 하나만 실제 API 호출로 바꾸면 됨.
- **장바구니 + 구매/환불**: 팝업에서 "담기"를 누르면 상단바 🛒 카운트가 올라가고, 🛒 버튼을 누르면
  담긴 상품/수량/합계와 "구매하기" 버튼이 뜬다. 구매하면 잔액이 차감되고, 그 상품들의 재고가
  줄고(`src/api/products.ts`의 세션 내 재고 오버레이), 장바구니는 비워지며 "구매 내역"으로 이동한다.
  구매 내역에서 "환불하기"를 누르면 잔액이 복구되고 그 상품의 재고도 원래대로 돌아간다.
  **주의: 진짜 결제/DB가 아니라 프론트 메모리에서만 일어나는 시뮬레이션이라 새로고침하면
  잔액·재고·구매내역이 전부 초기화된다.**
- **상단바 잔액 표시($)**: 초기값 99,999,999원, 구매/환불에 따라 실제로 오르내림(단, 위처럼
  새로고침하면 초기화). 실제 결제 API가 생기면 여기 연결해야 함.
- **AI 챗 팝업**: 상단바 버튼으로 열리는 채팅 UI는 만들어져 있지만, 실제 AI/백엔드 연동은
  안 돼있고 무엇을 입력해도 미리 정해둔 안내 문구만 돌려주는 스텁이다.
- **캐릭터의 "실제 층" vs "보는 층" 분리**: 캐릭터는 반드시 에스컬레이터/엘리베이터를
  실제로 밟고 스페이스바를 눌러야만(또는 다른 층 매대를 클릭 후 이동수단을 선택해야만)
  층이 바뀐다. 상단바 층 드롭다운으로 다른 층을 미리 봐도 캐릭터는 원래 층에 그대로 있음.
- **층간 이동 오케스트레이션** (`src/game/trip.ts`): 다른 층의 매대를 클릭하면
  엘리베이터/에스컬레이터 선택 팝업 → 엘리베이터면 목표 층으로 즉시 이동, 에스컬레이터면
  중간층을 실제로 한 층씩 거쳐가며(연결이 인접 층끼리만 있음: 1↔2, 2↔3 — B1은 엘리베이터만)
  각 중간층에서 1초 머문 뒤 다음 층으로 넘어감 → 마지막 층 도착 후 실제 목적지 매대까지 도보 이동
- **그래픽 개선 시도 (2차, 되돌림)**: 첨부해주신 그래픽 소스로 캐릭터/시설물/바닥을 실제
  이미지 스프라이트로 한 번 교체해봤으나, 결과물이 기존 벡터 스타일보다 낫지 않다고
  판단되어 그래픽만 원래(벡터) 스타일로 되돌렸다. 배경 제거해 뽑아둔 이미지들
  (`src/assets/character/*.png`, `src/assets/facilities/*.png`, `src/assets/floor_tile.png`)은
  프로젝트에 그대로 남겨뒀으니, 원하는 스타일로 다시 다듬어 붙이고 싶으면 재사용할 수 있다.
  (`StoreScene.ts`는 현재 이 이미지들을 참조하지 않는 순수 벡터 렌더링으로 돌아가 있다.)
- **1F/2F 매대·글자 겹침 수정 + 매장 확장**: 존 이름표(A/D/반려용품/엘리베이터 등)가
  매대와 겹쳐 보이던 문제 두 가지를 고쳤다.
  1. 이름표 위치를 "그 존 배열에서 처음 나온 매대 좌표"가 아니라 **그 존에 속한 모든
     매대의 실제 바운딩박스 좌측 상단(min-x, min-y)** 기준으로 계산하도록 바꿨고, 혹시
     그 자리도 매대로 막혀 있으면 통행 가능한 칸을 찾을 때까지 위로 올라가며 배치한다
     (`StoreScene.buildFloor()`). 이 로직은 새 존이 추가돼도 항상 좌측 상단 기준으로
     자동으로 계산되므로, 새로 맵을 만들 때도 이름표가 매대에 겹치지 않는다.
  2. 매대 구역과 시설물(엘리베이터/에스컬레이터/화장실) 열 사이 간격이 좁아서 생기던
     겹침을 해결하기 위해 그리드를 가로로 6칸(`WIDEN=6`, `gen_floor_json2.py`) 더 넓히고
     시설물을 전부 그만큼 오른쪽으로 밀었다 (`src/data/floor{1,2,3}.json`).
- **초록색 경로 안내선(패스파인딩 가이드라인) 복구**: 층을 한 번이라도 전환하면 그
  이후로는 안내선이 안 보이던 버그를 고쳤다. 원인은 층 전환마다 바닥 배경 그래픽 객체를
  새로 만들면서 그게 display list 맨 위로 다시 추가돼, 원래 있던(더 오래된) 안내선 객체를
  가려버린 것 — 이제는 모든 레이어(바닥/매대/이름표/시설물/경로선/캐릭터)에 명시적으로
  `setDepth()`를 지정해서 몇 번을 오가며 층을 바꿔도 쌓이는 순서가 항상 고정되도록 했다.

## 다음 단계 (아직 없음 — 설계만 되어 있고 구현 안 됨)

1. **백엔드 연동**: `src/api/locations.ts`의 `fetchFloorData`를 실제
   `GET /api/locations?floor=N` 호출로 교체. 응답 형식은 `src/game/types.ts`의
   `FloorData`와 맞추면 프론트 코드 변경 없이 바로 붙는다.

2. **편의시설 좌표 재검증**: 위에 적었듯 엘리베이터/에스컬레이터/화장실 좌표는 실제
   도면 근거가 없는 placeholder. 실제 배치가 확정되면 `src/data/floor{0,1,2,3}.json`의
   `facilities` 배열만 좌표를 바꾸면 나머지 로직은 그대로 동작함.

3. **상품/재고 데이터 실제 연동**: 매대 진열 상품 팝업은 지금 가짜 데이터(`src/api/products.ts`).
   실제 `products_seed.sql` 기반 API가 준비되면 `fetchProductsAtLocation`만 교체.

4. **장바구니/구매/환불 → 실제 백엔드 반영**: 구매·환불로 잔액과 재고가 오르내리는 건
   되지만 전부 프론트 메모리 상태(새로고침하면 초기화)일 뿐, 실제 DB/결제 API와는
   연결돼 있지 않음. 실제 결제·재고 API가 생기면 `handleCheckout`/`handleRefund`
   (App.tsx)와 `adjustStock`(products.ts)을 그 호출로 교체하면 됨.

5. **AI 챗 실제 연동**: `src/components/AIChatModal.tsx`는 UI만 있고 tool-calling 기반
   실제 응답(getProductLocation/getStock 등)은 미구현 — 지금은 고정 문구만 돌려줌.

6. **B1 실제 도면**: 현재 B1은 실제 도면이 없어서 임시로 단순 격자+랙 배치만 넣은 상태.
   실제 지하 창고 도면이 나오면 1F/2F/3F와 같은 방식(OpenCV 좌표 추출)으로 다시 만들어야 함.

7. **map_cells(보행 격자)**: 지금은 "매대가 없는 칸 = 통행 가능"으로 단순 처리.
   실제로는 매대 사이 통로 폭, 벽, 기둥 등을 반영한 정밀한 격자가 필요하면
   `occupied` 배열을 확장하거나 스키마의 `map_cells` 테이블을 그대로 가져와야 함.

8. **NPC 직원**: 프론트 시뮬레이션 수준으로는 구현됨 (`StoreScene.ts`) — 층마다 "직원"
   태그를 단 주황색 NPC 2명이 자동으로 돌아다니며 재고가 `LOW_STOCK_THRESHOLD`(5개)
   미만인 매대를 찾아 `findPath`로 걸어가서 `RESTOCK_QTY`(15개)만큼 채워 넣고,
   재입고할 곳이 없으면 잠깐 배회하다 다시 확인하는 루프를 돈다. 여러 NPC가 동시에
   같은 매대로 몰리지 않도록 스캔+선점을 큐로 직렬화(`claimLowStockTarget`)해뒀다.
   다만 아래는 여전히 실제 백엔드 연동이 필요한 부분:
   - `src/api/products.ts`의 재고 자체가 여전히 위치 시드 기반 가짜 데이터라, NPC가
     "채우는" 재고도 실제 DB 수량이 아니라 프론트 메모리(`stockOverlay`)일 뿐임
   - `src/api/locations.ts`의 `fetchLowStockTargets`는 실제로 로컬 데이터를 스캔해서
     동작하지만, 백엔드가 준비되면 `GET /api/inventory/low-stock` 한 줄로 교체하면 됨
   - 매대 도착 시 `confirmRestock()`을 호출하긴 하지만 지금은 콘솔 로그만 찍는 스텁 —
     실제 DB 수량 반영은 안 됨
   - 스키마의 `shelf_events` 8종(BELOW_PAR→TASK_QUEUED→TASK_STARTED→ITEM_CONFIRMED)
     흐름과 이름을 맞춰뒀으니 백엔드 이벤트 발행 순서와 그대로 대응시키면 됨
   - NPC 수/속도/임계값은 `StoreScene.ts` 상단의 `NPC_COUNT`/`NPC_SPEED`/
     `LOW_STOCK_THRESHOLD`/`RESTOCK_QTY` 상수로 조절 가능

9. **다중 경유지 쇼핑 경로** (예: "1층에서 고기 담고 화장실 들렀다가 2층에서 다른거
   구매"): 지금 구현된 건 "층 이동" 자체(엘리베이터/에스컬레이터를 실제로 타는 것)뿐이고,
   화장실 같은 편의시설을 경유지로 넣어서 하나의 이어지는 쇼핑 경로를 자동 계획하는 기능은
   아직 없음. `findPath(start, waypoint1)` + `findPath(waypoint1, waypoint2)` 식으로
   이어붙이고, 층이 바뀌는 구간에서는 `runTrip`을 재사용하면 될 것 (astar.ts, trip.ts 주석 참고).
   예상 쇼핑시간 계산도 이 경로 길이(칸 수) 기반으로 붙이면 됨 — 아직 미구현.

10. **매대(선반) 실제 그래픽**: 지금은 색상 사각형(벡터)이다. 첨부받은 시트 중
    `대형선반진열대타일셋.jpg` 등은 정면/입체 시점이라 이번엔 일부러 안 썼다 — 완전
    톱다운 시점의 선반 스프라이트가 따로 준비되면 `StoreScene.buildFloor()`의
    매대 렌더링 부분만 이미지로 교체하면 됨.
11. **카테고리별 매대 그래픽**: 첨부 zip에는 음료/과일/정육/생활용품 등 구역별
    카테고리 사진도 있었지만, 이번 라운드에서는 사용하지 않았다(정면 시점 문제는
    위와 동일). 존별로 실제 상품 아이콘을 넣고 싶다면 다음 라운드에서 톱다운 스타일로
    다시 다듬어서 붙이면 된다.

## 좌표 규칙

- 원점(0,0) = 각 층 도면 좌측 상단
- x = 오른쪽 증가, y = 아래쪽 증가
- 그리드 1칸 = 도면 원본 20px (PITCH) — Phaser 렌더링에서는 16px 타일로 그림(TILE 상수, `StoreScene.ts`)
- `location_id` 형식은 `db/schema_v2.sql`과 동일: `F{층}-{존}-R{랙}-B{베이}-L{레벨}`
- level_no는 전부 2(PICK 대표값)만 있음 — 수직 BULK 재고(L5)는 이 데이터에 없음(후속 작업)
