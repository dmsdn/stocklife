# STOCKLIFE 매장 시뮬레이션 (Simulation)

**매장 안에서 일어나는 상황을 한눈에 이해할 수 있도록 만든 시뮬레이션**.
STOCKLIFE는 실제 창고형 마트 안에서 쓰는 서비스인데, 발표나 시연 자리에는 실제 매장이 없습니다.
그래서 매장을 화면 위에 그대로 옮겨, **손님이 어디에 있고, 어느 방향으로 이동하며, 어떤 매대 앞에서 무엇을 찍는지**를 앱 화면과 나란히 보여줄 수 있도록 구현했습니다.

> 담당: 팀원

<br>

## 왜 필요했나

앱 화면만으로는 매장 안의 상황이 잘 전달되지 않는다 판단했습니다.
- "다음 상품은 2층 D구역이에요"라는 안내가 **실제로 어디를 말하는지**
- 동선 안내가 **층을 오르내리지 않고 효율적으로** 짜였는지
- 리브가 "찾던 상품이 다시 들어왔어요"라고 말을 거는 순간, **매장에서는 무슨 일이 있었는지**

시뮬레이션은 왼쪽에 매장을, 오른쪽에 실제 앱(frontend)을 함께 띄워 이 연결을 눈으로 보여줍니다.

```
┌──────────────────────────────┬──────────────┐
│  매장 시뮬레이션 (Phaser)      │  STOCKLIFE   │
│  · 층별 매대 · 시설            │  앱 화면     │
│  · 손님 캐릭터 · 이동 경로     │  (iframe)    │
│  · 매대 바코드 표시            │              │
└──────────────────────────────┴──────────────┘
          ▲ 로그인 · 스캔 · 동선 정보를 서로 주고받음 ▲
```

<br>

## 주요 기능

### 매장 재현
- 실제 매장 도면을 바탕으로 **1F · 2F · 3F 매대와 구역**을 그립니다. 매대 위치와 걸을 수 있는 통로는 백엔드 DB의 지도 데이터를 그대로 사용합니다.
- 엘리베이터 · 에스컬레이터 · 화장실 · 계산대 같은 **시설과 서비스 구역**도 함께 표시
- 층 보기 전환, 마우스 휠 확대 · 축소, 드래그로 화면 이동

### 손님 캐릭터 이동
- 방향키로 걷거나, 매대를 클릭하면 **A\* 최단 경로**로 자동 이동
- 다른 층을 고르면 엘리베이터 · 에스컬레이터 중 선택해 **실제로 타고 이동** (에스컬레이터는 방향이 있고, 인접한 층끼리만 이동)
- 매대 앞에서 그 매대의 상품 목록 확인, 리스트에 담기

### 앱과 함께 움직이는 장보기 안내
- 앱에서 만든 장보기 리스트를 불러와, 리스트 상품을 **방문 순서대로 동선을 그리고 캐릭터가 따라 이동**
- 같은 층을 먼저 다 돌고 다음 층으로 가도록 방문 순서를 정합니다.
- 경로는 앱의 동선 안내와 **같은 백엔드 API**로 계산해서, 두 화면의 경로가 일치합니다.
- 앱에서 상품 위치를 누르면 시뮬레이션 지도에 **핀으로 표시**

### 바코드로 연결되는 시연
- 매대 앞에서 상품이나 시설의 **바코드를 화면에 띄워요.** 오른쪽 앱의 카메라로 이 바코드를 찍으면 실제 매장에서 스캔한 것처럼 동작합니다.
- 바코드를 찍은 매대를 출발점으로 삼아 **"지금 위치부터" 동선을 다시** 짤 수 있습니다.

### 매장 상황 만들기
- **재고 채우기**: 매대 재고를 늘리는 이벤트를 백엔드에 보내요. 이 변화가 Agent로 전달되면, 그 상품을 기다리던 손님에게 리브가 **먼저 말을 거는 장면**을 시연할 수 있습니다.
- 결제하면 실제 재고가 줄고, 매대 상품 목록에 바로 반영됩니다.

### 로그인 공유
앱에서 로그인한 계정을 시뮬레이션 캐릭터도 그대로 따라갑니다.
앱과 시뮬레이션을 **같은 주소(origin) 아래**에 두어 로그인 정보를 공유하고, 로그인 · 로그아웃 · 스캔 · 장바구니 변경을 서로 메시지로 알려줍니다.

## 기술 스택

| 구분 | 사용 기술 |
|---|---|
| 게임 엔진 | Phaser 3 |
| UI | React 18, TypeScript |
| 빌드 | Vite |
| 길찾기 | A\* (격자 기반), 층 연결 그래프 |
| 앱 연동 | iframe + postMessage |

<br>

## 폴더 구조

```
Simulation/
├── src/
│   ├── App.tsx                  # 전체 화면, 앱과의 메시지 처리, 장보기 안내 흐름
│   ├── game/
│   │   ├── scenes/StoreScene.ts # 층 그리기, 캐릭터 이동 (Phaser Scene)
│   │   ├── pathfinding/astar.ts # 격자 최단 경로
│   │   ├── floorGraph.ts        # 엘리베이터 · 에스컬레이터 층 연결 규칙
│   │   └── trip.ts              # 다른 층으로 이동하는 계획 실행
│   ├── components/              # 상품 · 리스트 · 결제 · 층 이동 · 바코드 · 앱 패널
│   ├── api/                     # 백엔드 연동 (지도, 상품, 리스트, 동선, 채팅, 로그인)
│   ├── data/                    # 층별 시설 · 서비스 구역 배치
│   └── state/                   # 현재 로그인한 손님
├── scripts/                     # 바코드 · 경로 · 에스컬레이터 · 로그인 검사
└── vite.config.ts               # 개발 서버 프록시 (백엔드 · 앱을 같은 주소로)
```

## 실행 방법

백엔드(8080)와 앱(frontend, 3000)이 먼저 켜져 있어야 합니다.

```powershell
npm install
$env:INTERNAL_SERVICE_KEY="<백엔드 internal.service-key와 같은 값>"
npm run dev
```

| 화면 | 주소 |
|---|---|
| **시뮬레이션 + 앱** | http://localhost:5173/simulation/ |
| 앱 단독 (같은 주소 아래) | http://localhost:5173/ |

- 개발 서버가 `/api`, `/internal`은 백엔드로, 나머지 경로는 앱(3000)으로 전달합니다. 배포 환경(앱은 `/`, 시뮬레이션은 `/simulation/`)과 같은 구조라 로그인 정보가 공유됩니다.
- `/internal` 요청에 필요한 서비스 키는 개발 서버가 대신 붙여줍니다. 브라우저 코드에는 키가 들어가지 않습니다.

```powershell
npm run build        # 배포용 빌드 (/simulation/ 경로 기준)
npm run test:auth    # 로그인 · 바코드 · 경로 · 에스컬레이터 검사
```
