# STOCKLIFE 소비자 모바일 웹 (frontend)

장보기 리스트를 만들고, 매장에서 동선 안내를 받으며 바코드로 상품을 담고, 앱으로 결제하는 **소비자용 모바일 웹**.

## 기술 스택

| 구분 | 사용 기술 |
|---|---|
| 프레임워크 | Next.js 16 (App Router), React 19 |
| 언어 | TypeScript |

## 주요 화면

### 계획
- **홈**: 오늘의 장보기 상태, 리브와 계획 세우기, 매장 지도 · 상품 검색 진입, 소비 분석 요약
- **검색**: 상품 검색과 카테고리 · 가격 · 판매 상태 필터, 원하는 리스트에 바로 저장
- **기록(리스트 · 리브)**: 장보기 리스트 여러 개 관리, 리브와 나눈 대화 목록 검색
- **리스트 상세**: 상품마다 매장 위치(층 · 구역) 표시, 수량 조절, 리브에게 물어보기

### 리브(AI 도우미)
- 텍스트 대화로 상품 비교 · 추천, 답변 속 상품을 리스트에 바로 담기
- **음성 입력**: 말하는 동안 실시간으로 글자로 바뀌어 입력창에 채워짐
- **사진 첨부**: 사진 속 상품을 인식해 매장 상품과 연결
- 리브가 **먼저 보낸 메시지**를 실시간으로 받아 대화창과 알림함에 표시

### 매장에서
- **장보러 가기 → 매장 모드**: 리스트 상품의 위치를 층별 지도에 표시하고 방문 순서대로 동선 안내
- **Scan & Go**: 카메라로 바코드를 찍으면 바로 담기고, 다음 위치로 안내. 바코드 번호 직접 입력도 가능
- 담은 상품 목록은 하단 시트로 표시 (평소엔 최근 상품 1개, 누르면 전체 목록)
- 쇼핑 중에 새 상품을 리스트에 추가

### 결제 · 마이페이지
- 포인트 사용, 결제수단 선택, 결제 완료 후 **전자영수증**
- 소비 분석(1개월 · 1년 · 전체), 주문 · 영수증 내역, 포인트, 쿠폰, 알림 설정, 권한 설정, 회원정보 수정

### 회원
- 전화번호 인증 회원가입 → 생년월일 · 성별 · 가구원 수 · 반려동물 · 차량 · 자녀 정보 입력 (건너뛰기 가능)
- **비회원으로도 리스트를 만들 수 있고**, 가입하면 그 리스트가 회원 계정으로 옮겨짐

## 구현하면서 고민한 부분

### 1. 어느 기기에서나 되는 바코드 스캔
처음에는 브라우저 내장 BarcodeDetector API를 썼는데, **안드로이드 크롬에서만 동작**하고 아이폰(Safari · 크롬 모두)과 PC 브라우저에서는 아예 없었습니다.
카메라 영상을 JS로 직접 분석하는 `@zxing/library`로 바꿔서 기기와 브라우저에 상관없이 스캔되도록 수정했습니다.
권한은 열려 있는데 모바일 크롬에서 카메라가 안 켜지던 문제도 함께 해결했습니다.

### 2. 동선 안내가 처음으로 돌아가던 문제
에스컬레이터 도착 확인이나 "먼저 들르기"를 누를 때마다 **전체 경로를 다시 계산**해서, 이미 정해진 방문 순서가 매번 뒤섞이는 문제가 있었습니다.
처음 정한 방문 순서는 유지하고, 진행 상황만 갱신하는 방식으로 바꿨습니다. 이 로직은 테스트 코드(`tests/shopping-route-progress.test.mjs`)로 검증합니다.

### 3. 비회원 리스트 승계에서 생긴 의도치 않은 데이터
비회원이 처음 앱을 열면 데모 리스트 3개를 자동으로 만들어두던 코드가 있었는데, 로그인하면 그 리스트까지 **회원 DB로 그대로 옮겨져** "직접 만들지 않은 리스트가 생긴다"는 문제가 있었습니다.
자동 생성을 없애고, 사용자가 실제로 만든 리스트만 승계되도록 수정했습니다.

### 4. 리브가 먼저 보낸 메시지를 놓치지 않기
리브가 먼저 말을 걸면 백엔드가 SSE로 보내주는데, 받는 쪽이 없어서 **채팅창을 다시 열어야** 보였습니다.
앱 전체에서 SSE를 하나만 구독하고, 받은 메시지를 열려 있는 채팅창에 바로 붙이거나 닫혀 있으면 배지로 표시하도록 수정했습니다.
이 메시지는 알림함에도 남지 않았어서, 받는 순간 로컬에도 저장해 서버 알림과 합쳐서 보여줍니다.

### 5. 음성 입력은 되는 브라우저에서만, 안 되면 자연스럽게
별도 음성 인식 서버 없이 브라우저 내장 Web Speech API로 말하는 동안 바로 텍스트로 바뀝니다.
지원하지 않는 브라우저에서는 녹음 파일 첨부로 자동 전환됩니다.

### 6. PC에서도 모바일 화면으로
모바일 기준으로 설계한 앱이라, PC 화면에서 데스크톱용 스타일이 섞여 레이아웃이 어색하게 커지는 문제가 있었습니다.
화면 폭과 상관없이 모바일 레이아웃이 유지되도록 반응형 기준을 없애고, PC에서는 가로 430px 화면 틀에 띄우도록 수정했습니다.
하단 탭바 · 모달 · 바텀시트가 브라우저 전체가 아니라 이 틀을 기준으로 붙도록 맞췄고, 휴대폰에서는 틀 없이 화면 전체를 채우게 됩니다.

## 폴더 구조

```
frontend/
├── app/
│   ├── (main)/                # 하단 탭바가 있는 메인 화면들
│   │   ├── page.tsx           # 홈
│   │   ├── search/            # 검색
│   │   ├── saved/             # 기록(리스트 · 리브 대화), [groupId] 리스트 상세
│   │   ├── scan/              # 매장 모드 · Scan & Go
│   │   ├── store-map/         # 매장 지도
│   │   ├── cart/ · checkout/  # 결제
│   │   ├── product/[skuId]/   # 상품 상세
│   │   ├── notifications/     # 알림함
│   │   └── mypage/            # 마이페이지 (소비 분석, 주문, 포인트, 설정 등)
│   └── auth/                  # 로그인, 회원가입, 비밀번호 재설정
├── components/
│   ├── ai/                    # 리브 채팅
│   ├── home/                  # 홈 섹션
│   ├── domain/                # 지도, 스캔, 결제, 필터 등 기능 컴포넌트
│   ├── layout/                # 앱 화면 틀, 하단 탭바, 리브 패널
│   └── ui/                    # 공용 UI
├── lib/                       # API 호출, 장바구니 · 동선 · 실시간 수신 로직
├── scripts/ · tests/          # 연동 검사, 동선 로직 테스트
└── public/                    # 이미지, 지도, 아이콘
```

## 실행 방법

```powershell
npm install
Copy-Item .env.example .env.local   # 필요할 때만
npm run dev
```

`http://localhost:3000`에서 열려요. `/api` 요청은 `next.config.ts`의 rewrites가 백엔드(`http://127.0.0.1:8080`)로 전달해요. 백엔드가 꺼져 있으면 화면은 열리지만 데이터가 보이지 않아요.

| 환경변수 | 필수 | 설명 |
|---|---|---|
| `BACKEND_BASE_URL` | | 프록시할 백엔드 주소 (기본 `http://127.0.0.1:8080`) |
| `NEXT_PUBLIC_API_BASE_URL` | | API를 별도 주소로 직접 호출할 때만 사용 |

```powershell
npm run test:routes         # 동선 진행 로직 테스트
npm run test:integration    # 백엔드 연동 검사 (백엔드 실행 필요)
```
